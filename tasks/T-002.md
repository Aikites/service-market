# T-002 竞标大厅认证

## 1. 背景与边界

T-001 的竞标大厅是一个只读 Node 服务：`server.js` 提供 `/api/bids`、`/api/bid-result`、`/api/budget`，页面是 `index.html`。它没有账号、没有会话、没有角色；`admin.html` 目前是 0 字节占位，`README.md` 和 `.env.example` 也是空文件。

本卡只做**人的认证**：

- 需求方/运营人员可以注册、登录、登出
- 登录后能看到「我的账号」
- ADMIN 可以打开 `/admin.html`
- 未登录/USER 不能打开管理页
- 投标仍然是 `bids/T-001/*.json` 的 AI Agent 投标，不要求 Agent 登录；认证不改变 T-001 的评分和预算

明确不做：竞标发布、选标、支付、社区、邮件验证、找回密码、OAuth、审计后台。

## 2. 前置与阻塞

1. T-001 必须先从 draft 冻结：补 `human_approval`、`task_sha256`、真实 verify/review 报告。
2. 本仓库当前没有数据库、没有 Prisma、`package.json` 没有运行时依赖。T-002 v0 用 **文件存储**，不引入依赖。
3. 如果人类要求「DB Session 表」，必须先做 T-001.5 持久化地基（选 SQLite/Prisma），T-002 不能同时承担建库和认证。
4. `docs/invariants.json` 是受保护文件。本卡不新增 INV ID；`invariants` 取 T-001 的 INV-001..003，表示不得破坏预算/评分/只读 API。
5. 认证安全由 `required_tests` + acceptance 覆盖；如果要把它升级成正式 invariant，必须由人类另开卡并实现 `scripts/verify.mjs` 的 check kind。

## 3. 存储设计（v0 文件存储）

新增 `src/auth/store.mjs`，默认数据文件 `data/auth.json`，可用 `AUTH_DATA_FILE` 覆盖（测试必须用临时文件）：

```json
{
  "version": 1,
  "users": [
    {
      "id": "usr_...",
      "email": "user@example.com",
      "name": "用户",
      "passwordHash": "scrypt$16384$8$1$...$...",
      "role": "USER",
      "createdAt": "2026-11-19T00:00:00.000Z",
      "updatedAt": "2026-11-19T00:00:00.000Z"
    }
  ],
  "sessions": [
    {
      "id": "ses_...",
      "tokenHash": "sha256 hex",
      "userId": "usr_...",
      "createdAt": "2026-11-19T00:00:00.000Z",
      "expiresAt": "2026-11-26T00:00:00.000Z",
      "lastSeenAt": "2026-11-19T00:00:00.000Z"
    }
  ]
}
```

要求：

- 目录不存在时创建；写文件用 `auth.json.tmp` + `rename` 原子替换
- 同一进程内的写操作用 Promise 队列串行，避免并发写坏文件
- 读文件时过滤过期会话；登录/登出时清理旧会话
- `data/` 加入 `.gitignore`；仓库里不能提交真实用户或会话
- 文件权限尽量 `0o600`（Windows 上忽略）

## 4. 密码与会话

### 4.1 密码

新增 `src/auth/password.mjs`：

- `scrypt`，N=16384、r=8、p=1、16 字节盐、64 字节 key
- 存储格式：`scrypt$N$r$p$saltBase64$hashBase64`
- `verifyPassword` 对格式/参数做上下界校验，失败返回 false，不抛 500
- 登录时邮箱不存在也跑一次 dummy scrypt，降低时序差
- 密码 8–72 位；拒绝常见弱口令、纯数字、与邮箱 local part 相同
- 禁止明文、可逆加密、MD5/SHA1 单次哈希

### 4.2 会话

新增 `src/auth/session.mjs`：

- token：`randomBytes(32).toString("base64url")`
- 存储只保存 `sha256(token)`，不保存原文
- TTL 7 天；每次读取更新 `lastSeenAt`（可选，不延长 exp）
- 登录成功：先删除该用户旧会话，再创建新会话（轮换）
- 登出：删除当前会话并清 Cookie
- 过期/被删/哈希不匹配一律按未登录
- 不实现「记住我」、多设备管理、刷新 token

Cookie：

- 名：`sm_session`
- `HttpOnly`、`SameSite=Lax`、`Path=/`
- `NODE_ENV=production` 时加 `Secure`
- `Max-Age=604800`
- 登出 `Max-Age=0`

## 5. 接口契约

所有 JSON 请求要求 `content-type: application/json`，body 上限 16 KB。响应统一：

```json
{ "ok": true, "user": { "id": "...", "email": "...", "name": "...", "role": "USER", "createdAt": "..." } }
```

错误统一：

```json
{ "ok": false, "error": "..." }
```

### POST /api/auth/register

请求：

```json
{ "email": "user@example.com", "password": "correct horse battery", "name": "用户" }
```

- email：trim + lowercase，最长 254，合法邮箱
- name：trim 后 2–30 字
- password：8–72 位，弱口令拒绝
- 成功：201，写 Set-Cookie，返回 user（不含 passwordHash）
- 重复邮箱：409
- 字段非法/弱口令：400
- 注册限流：同一 IP 每小时最多 10 次（内存实现，写清楚多实例失效）
- **role 固定 USER**；请求里的 role 字段一律忽略，不能自升 ADMIN

### POST /api/auth/login

请求：

```json
{ "email": "user@example.com", "password": "..." }
```

- 成功：200，写新 Set-Cookie，返回 user
- 邮箱不存在/密码错误：统一 401「邮箱或密码错误」
- 邮箱不存在也执行 dummy scrypt
- 失败限流：`IP + email` 1 分钟最多 5 次；第 6 次 429，带 `Retry-After`
- 成功登录清空失败计数

### POST /api/auth/logout

- 删除服务端会话，清 Cookie
- 返回 200 `{ "ok": true }`
- 未登录也返回 200（幂等）

### GET /api/auth/me

- 有有效会话：200 `{ "ok": true, "user": ... }`
- 无/过期/被撤销：401 `{ "ok": false, "error": "未登录" }`

## 6. 静态页面与角色中间件

新增：

- `login.html`：邮箱 + 密码，成功后跳 `next` 或 `/`
- `register.html`：称呼 + 邮箱 + 密码，成功后跳 `/`
- `admin.html`：最小管理员页，显示当前用户、角色、会话到期时间；只允许 ADMIN
- `index.html`：右上角增加「登录 / 注册 / 我的账号 / 退出」，用 fetch `/api/auth/me` 渲染；不破坏现有投标列表

服务端：

- `/login`、`/register` 映射到对应 HTML
- `/admin.html`：
  - 未登录：302 `Location: /login?next=/admin.html`
  - USER：403 文本页
  - ADMIN：200 返回 `admin.html`
- `requireUser(req)` / `requireAdmin(req)` 放在 `src/auth/middleware.mjs`，供后续管理接口复用
- 登录后的 `next` 只允许以单个 `/` 开头且不以 `//` 开头，防开放重定向
- 认证失败不能把内部错误堆栈返回给客户端

管理员引导：

- 环境变量 `ADMIN_EMAIL` / `ADMIN_PASSWORD`
- 启动或首次注册时，如果 `ADMIN_EMAIL` 存在且库里没有该邮箱，创建 ADMIN（密码必须 8–72，弱口令拒绝）
- 已存在同名用户不改角色/密码；不提供默认管理员密码
- `.env.example` 只放占位值，不能放真实密码

## 7. 安全规则

- 密码/会话/管理员密码不进日志、不进响应、不进 git
- 所有写接口从服务端会话取用户，不信任 body/query 里的 userId/role
- Cookie 不设置 `Domain`，避免子域共享
- POST 请求若带 `Origin`，必须与请求 Host 同源；不同源 403
- 错误文案不区分「邮箱不存在」和「密码错误」
- 登录/注册限流用内存 Map；文件注释写明多实例失效
- 文件存储不是生产数据库；上线前换 SQLite/Postgres，并迁移用户/会话

## 11. 风险与回滚

- **文件存储并发**：JSON 文件不是数据库；必须原子写 + 串行队列。多实例会互相覆盖，明确 v0 单实例。
- **会话轮换**：删除旧会话要按 userId，不是按 token；否则第二次登录旧会话仍有效。
- **提权**：注册只允许 USER；管理员只能由环境变量引导，不能由前端指定。
- **开放重定向**：`next` 必须站内路径；拒绝 `//`、反斜杠、控制字符。
- **T-001 回归**：认证改动不得改 `src/bid` 或预算/评分；手工核对三条只读 API。
- **数据文件泄漏**：`data/` 必须 gitignore；日志不打印密码/token。
- 回滚：删除新增 auth 文件、还原 `server.js`/`index.html`/`admin.html`/`.env.example`/`.gitignore`；删除 `data/`；T-001 只读 API 不受影响。
